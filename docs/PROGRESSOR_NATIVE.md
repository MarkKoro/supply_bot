# Нативные связи Progressor: контракт для следующих изменений

Версия правил: 2026-10-08. Перед изменением читать также [основной контракт](../README.md). Этот документ объясняет, зачем нужны новые расчёты, условия показа и ограничения ИИ. Домены сохраняют свои базы, API, права и основные функции при недоступном Core.

## Кто владеет чем

| Участок | Ответственность |
|---|---|
| Gym `db.mark_day_completed` / `workout_session_details` | Атомарное завершение собственной сессии, сохранённая человеком длительность. Повтор завершения того же дня/программы/сессии не создаёт вторую историю и не стирает прежнюю длительность. |
| Gym `progressor_workout_metrics.py` | Чистый расчёт рабочих подходов, повторов, внешнего объёма и удержаний по своей записи. Не обращается к ИИ или другим базам. |
| Food `billing.preflight_meal` и сохранение | Проверка подписки/trial/PAYG/суточной квоты до провайдера и атомарно при сохранении. Повтор сохранённого source key не вызывает ИИ и не списывает снова. |
| Food `nutrients.py` | Наблюдения состава, неизвестные значения, единицы, источник, версии порций и покрытие. Изменение порции пересчитывается арифметикой. |
| Каждый `progressor_ai_guard.py` | Собственная SQLite таблица `progressor_ai_attempts`: активная lease, пауза и предел попыток, включая ошибки. Не заменяет бизнес-квоты и баланс. |
| Supply `db.create_assistant_job` | Дедупликация активных jobs, месячное резервирование и отдельный счётчик попыток по Telegram id. Очистка пользовательского содержимого не должна обнулять защиту повторов. |
| Core `adapters.py` | Только чтение частных online snapshot от владельцев; сопоставление Telegram id, ревизии и стабильная проекция старых дублей завершений. Не удаляет историю Gym. |
| Core `native_insights.py` | Сравнение похожей нагрузки, условная энергия и правила подсказок. Только разрешённые свежие источники; никаких LLM-вызовов. |
| Core `context.py` / `ai_context.py` | Права, полнота, происхождение и ограниченный общий контекст. AI prompt `progressor.cross_context.v2`; не более 20 сводок занятий за 14 дней, без больших векторов каждого упражнения. |
| Core `hint_preferences` | Скрытие подсказок личного аккаунта отдельно в каждом продукте на 7 дней. |
| Core `shared/navigation.v1.js` + `window.ProgressorDomain` | Общая авторизация/навигация и одна карточка на собственном экране. Native hook версии 1 сообщает host, eligible и perform; DOM рендерит текст безопасно через textContent. |

Канонические helpers находятся в `MarkKoro/progressor_core/shared/`. `ai_guard.py` копируется дословно в `progressor_ai_guard.py` всех трёх репозиториев, `workout_metrics.py` — в Gym `progressor_workout_metrics.py`, `nutrition_plan.py` — только в Food `progressor_nutrition_plan.py`. Изменять canonical и все копии вместе. Не добавлять импорт серверного Core в домены. `progressor_client.py`, `progressor_bot.py`, `progressor_bridge.py` сохраняют прежние контракты.

## Энергия и изменение нагрузки

15 подходов по 10 повторений дают 15 рабочих подходов и 150 повторений. Их нельзя честно превратить в универсальные ккал на повторение или по размеру мышцы: темп, нагрузка, амплитуда, паузы и человек различаются. [Исследование отдельных упражнений](https://pubmed.ncbi.nlm.nih.gov/28742112/), [обзор методов](https://pmc.ncbi.nlm.nih.gov/articles/PMC11393209/).

Оценка силовой энергии появляется только при сохранённой длительности 5–240 минут, подходящем весе и известной принадлежности к взрослому диапазону 19–59 лет. Возраст из года рождения — интервал, не придуманная точная дата рождения. Профили Food/Supply и измерения Gym разрешаются по полям и времени наблюдения; приоритет и конфликты описаны в [NATIVE_GROWTH.md](NATIVE_GROWTH.md). Supply должен быть оплачен, согласован и свеж. Без подходящих данных значение остаётся неизвестным. Профиль не заимствуется из неоплаченного продукта.

Модель `compendium_strength_2024.v1`: `MET × kg × hours`, 3.5–6 MET. Отдельно полный расход и сверх покоя `(MET−1) × kg × hours`. Например, 80 кг и 60 минут дают примерно 280–480 ккал всего и 200–400 сверх покоя. Диапазон категорий популяционной модели не является доверительным интервалом или измерением человека. EPOC не добавляется. [Авторы Compendium 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC10818145/), [таблица категорий](https://pacompendium.com/conditioning-exercise/).

При сравнении нагрузки требуются ≥3 сопоставимые предыдущие сессии той же программы и дня за 90 дней, не больше восьми последних. Сравниваются те же пользовательские упражнения и их режим: внешний вес / повторы / удержание. Медиана отношений объёма каждого упражнения ≥1.2 показывает «выше обычного». 20% — продуктовый порог показа, не физиологический порог усталости, травмы или расхода энергии. Внешний объём в кг×повторах не является работой в джоулях.

**Цель Food автоматически не увеличивается и не уменьшается**: привычная активность может уже входить в неё. Рост, возраст и вес не подставляются по умолчанию. Стандартный Adult Compendium не применяется к детям и пожилым; для них нужны отдельные основания и проверка.

## Подсказки и нативные действия

| Где | Условия | Что показывается и что делает кнопка |
|---|---|---|
| Food, текущий день | Свежая разрешённая завершённая тренировка | Рабочие подходы/повторы, сравнение с привычной нагрузкой, энергия только при достаточных данных. Кнопка прокручивает и фокусирует собственный журнал, не запускает ИИ. На вчерашнем питании карточка скрыта. |
| Gym личный дневник / Supply | ≥3 записанных дня, белок ниже 80% текущей своей цели Food | Предложение проверить полноту и цель. Кнопка открывает доступное питание. 80% — правило интерфейса, не диагноз недоедания. |
| Supply, «Сегодня» | ≥5 записанных дней, ≥10 блюд, известны все записанные дни и ≥80% блюд/компонентов данного нутриента | Обзор пищевых источников железа/B12. Основная кнопка открывает Food; «Уже принимаю — добавить» ищет вещество в собственном каталоге. Дальше обычный выбор и форма дозы пользователя. |

Для обзора источников внутренние консервативные пороги среднего по записанным дням: железо <4 мг, B12 <1.2 мкг. Они **не персональная потребность, не рекомендованная норма и не валидированный тест дефицита**. Не делать из этих чисел назначения. Неизвестные блюда и состав не считаются нулём. Данные `ai_estimate` приблизительные. При уже записанной соответствующей добавке дополнительная кнопка добавления не предлагается; текстовые дозы не складываются с едой.

История рациона не устанавливает клинический статус; железо не следует начинать лишь по этому дневнику. [NIH: железо](https://ods.od.nih.gov/factsheets/Iron-HealthProfessional/), [NIH: B12](https://ods.od.nih.gov/factsheets/VitaminB12-HealthProfessional/).

Для личного общего контекста оба продукта — источник и место показа — должны иметь доступ. Отсутствие продукта, оплаты или согласия не превращается в личный медицинский вывод или нулевой показатель. Допускается отдельно помеченный статический пример общей подписки без закрытых данных. При устаревшем источнике связанная подсказка прекращается, native функции продолжают работать. Gym acting/trainer mode не показывает личную inline карточку в дневнике подопечного и не передаёт его Food/Supply в ИИ. Общая явно личная панель остаётся аккаунтом запросившего человека.

Одна inline карточка по приоритету, без звука/модального окна при синхронизации; отдельно включаемые Food reminders описаны в [NATIVE_GROWTH.md](NATIVE_GROWTH.md). Подробности скрыты под «Почему эта подсказка». Крестик имеет aria-label «Скрыть подсказки на неделю» и сохраняет выбор на сервере. После закрытия не вставляется следующая карточка. Повторный refresh сохраняет раскрытие и DOM неизменённого совета. Каждый источник подписан. Кнопки ≥48 CSS px, перенос длинного текста, видимый keyboard focus, safe-area верхней панели; это практический web размер, не физическая эквивалентность Android dp. [Fluent 2](https://fluent2.microsoft.design/components/web/react/core/messagebar/usage), [Apple TipKit](https://developer.apple.com/documentation/tipkit/tips/configurationoption/displayfrequency(_:)), [Android accessibility](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views).

`POST /api/v1/me/hints/dismiss` принимает только target; подписанная core audience определяет владельца. Пользовательский user_id в теле не меняет аккаунт. Target проверяется по включённым доменам и доступу; размер тела ограничен. Откат additive схемы не требует восстановления прежней DB.

## Сколько ИИ вызывается

Просмотр, навигация, синхронизация, правила подсказок, энергия, сравнение нагрузки, каталог, исправление порции и закрытие карточки — **0 вызовов ИИ**.

| Действие | Предел попыток сверх существующей бизнес-квоты | Обычные этапы |
|---|---|---|
| Food анализ | 1 активная операция; 18/час, 100/сутки; 15с после неудачной попытки | Текст — анализ; фото — анализ с одним прежним fallback; голос — транскрипция + анализ. После успешного сохранения следующее отдельное блюдо допускается сразу. Повтор сохранённого сообщения не обращается к провайдеру. |
| Food цель | 0 вызовов ИИ | Опрос и WebApp используют детерминированный ориентир; preview не заменяет цель без явного сохранения. |
| Gym coach | 1 активная операция на verified requester; 6/час, 12/сутки, 15с | Запрос пользователя и максимум прежняя структурная коррекция. Смена подопечного не меняет requester. Дневная/недельная/месячная квота остаётся; провайдерная ошибка возвращает бизнес-квоту, но учитывает попытку. |
| Supply bot guidance/check-in | 1 активное действие; 6/час, 20/сутки, 15с | Голос/извлечение/ответ внутри одной операции; вложенные этапы той же async task используют одну lease. |
| Supply очередь | Активный job того же вида дедуплицируется; 6 созданий/час, 20/сутки, 15с | Сохраняется 5 nutrient_compute/месяц с прежним резервированием/возвратом. Cached объяснение неизменённых анализов не создаёт новый job. |

Lease 15 минут принадлежит token; завершение старой операции не снимает новую. Ошибки входят в ограничение попыток, чтобы возврат бизнес-квоты не превращался в бесконечные платные для сервера retries. В таблице только subject/scope/время/token/результат, без текста промптов и медицинских данных; очистка старых строк при следующих обращениях сохраняет 48ч окно операционной защиты. Существующие quota/permission/balance checks не снимать.

Supply SDK `max_retries=0`, timeout по умолчанию 60с; явные timeout существующих путей сохранены. Нутриент pipeline сохраняет один ограниченный timeout fallback и структурную обработку несовместимого параметра; в худшем таком сочетании до четырёх HTTP попыток в одной job, а не бесконечный повтор. Опрос/обычный вход не создают такую job. Не добавлять автоматический AI при завершении тренировки или изменении пищи.

## Проверки и выпуск

Модель/контекст: Core `tests/test_native_metrics.py`, `test_native_insights.py`, `test_native_api.py` и прежние integration/billing/source tests. Owner entrypoints: `tests/test_native_controls.py` каждого бота; Gym subscriptions/context tests, полный Food suite, Supply queue/SDK/bot guard tests. Провайдеры подменены: никакого реального платного запроса или дополнительного Telegram consumer.

При изменении запуска/auth/навигации проверять все 9 вход→раздел переходов, mobile widths 360/390/430, большой текст, date/screen/acting mode, открытые details при refresh, action/focus, hide/reload/account isolation, отсутствие горизонтальной прокрутки и неожиданных AI POST. Эмуляция браузера не является физическим испытанием iPhone или Telegram.

Перед production: свежие согласованные online SQLite backups + code/config/Git/Core pointer, restore integrity, off-server hash; совпадение GitHub commit с tested stage, точный whitelist diff; targeted code rollback без DB restore; ff-only синхронизация, один unit за раз, health/source freshness/число consumers. Live Food DB отслеживается Git и изменяется пользователями: её никогда не включать в patch, не reset/checkout/clean.

Новые таблицы additive. Rollback сохраняет существующую финансовую совместимость Progressor, bundle cache/outbox и все новые записи пользователей. Текущий список дальнейших идей — отдельный [backlog](https://github.com/MarkKoro/gym_diary_bot/blob/main/docs/PROGRESSOR_OPPORTUNITIES.md); ни одна идея из него не включается автоматически в этот выпуск.


Canonical Core source is now [MarkKoro/progressor_core](https://github.com/MarkKoro/progressor_core), published to main. Its production updater is `update-progressor` (`updatecore`). The former Gym integrations/progressor_core package has been removed. Core application code exists only in the separate Core repository; bots contain only their native adapters and owned data/UX logic. Bot-local shared helper copies still require synchronized bot main commits and native tests. Publish bot changes directly to main with a normal fast-forward update, as requested by the owner.


Новое дополнение: [NATIVE_GROWTH.md](NATIVE_GROWTH.md) содержит обе поверхности Gym, согласованный профиль, ориентир без ИИ, static subscription examples и opt-in sender. При изменении этих путей читать оба документа.
