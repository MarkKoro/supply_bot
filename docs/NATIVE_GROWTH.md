# Связи, профиль и напоминания: инструкции для следующих агентов

Код приложения Core хранится только в [MarkKoro/progressor_core/main](https://github.com/MarkKoro/progressor_core). Три бота сохраняют собственные базы, API, платежи и Telegram consumers. Навигация и карточка из Core доступны в каждом WebApp. Общий контекст связан с личным Telegram id; разрешение тренера Gym не открывает чужие Food/Supply.

## Одна карточка и предложение общей подписки

Core `offers.py` составляет **статический пример** пользы закрытой связи. Он читает сроки доступа, но не читает для рекламы закрытые тренировки, питание, профиль или анализы. Trial, gift и paid учитываются при формулировке предложения; trial не расширяет прежние права на личные данные других продуктов. С двумя доступными разделами показана связь с третьим, с тремя действующими оплаченными разделами предложение отсутствует. Бесплатный Gym тоже может показать пример. Supply показывает пример на экране продления после знакомства; экран первого знакомства не содержит рекламной карточки.

Личная полезная подсказка имеет приоритет. Максимум одна карточка в собственном текущем дне. Нет всплывающего рекламного окна. «Посмотреть общую подписку» открывает прежний общий каталог сроков/тарифов с существующими Stars/YooKassa путями; просмотр не создаёт платёж. Срок отдельной подписки не стирается покупкой общей.

Скрытие предложения записывается отдельно в `offer_preferences` на7 дней. Скрытая личная подсказка не заменяется рекламой. `hint_preferences` сохраняет выбор скрытия подсказок на7 дней. Интерфейс отправляет `hints/seen` лишь для текущей настоящей карточки, видимой минимум на60% не менее1 секунды в активном окне и не перекрытой другим экраном; источник и account берутся из подписанного запуска. Имена/даты карточек не берутся из произвольного body user_id.

## Обе поверхности Gym

Core читает обычное `day_completion_history` и явные выполненные упражнения `session_exercises` из «Сегодня / Упражнения» и «Все упражнения». В незавершённой сессии считаются только отмеченные упражнения и сохранённые неразминочные подходы/завершённое кардио. Пустые подходы, drafts, неотмеченные упражнения не считаются выполненной работой.

Одна сессия не становится двумя тренировками. При завершении полного дня частичная проекция заменяется проекцией завершения в одной транзакции reconcile. Прежние дубли истории и сессий того же логического дня исключаются. `recorded_session_count` — записанные сессии; `completed_workout_count` — явно завершённые занятия. Не представлять отметку одного упражнения как завершение всей тренировки. Повторная отметка сохраняет исходное done_at. Внесение старого дня сохраняет его дату и не вызывает уведомление.

Gym владеет `progressor_session_durations`. Длительность силовой части5–240 минут задаётся человеком, сохраняется только для своей сессии с выполненными рабочими подходами и возвращается в native UI. Она не выводится из повторений или количества мышц. Core остаётся read-only к snapshot Gym. Длительность кардио не складывается с силовой повторно.

## Согласование профиля

Food владеет `progressor_food_profile`: структурированные поля, UTC updated_at и sharing_enabled. Старые survey_answers уже хранились в bot_state JSON, но не имели времени наблюдения/валидации отдельных полей: **не мигрировать их с выдуманной датой**. Новый завершённый опрос сохраняет профиль; WebApp «Профиль и напоминания» позволяет его исправить. Свободные тексты аллергий, диагнозов и заметок не передаются в Core.

Передача профиля Food требует отдельного согласия, по умолчанию отключена. Отзыв удаляет соответствующую проекцию при следующем snapshot, обычно в течение минуты. Каждое исходное значение остаётся в базе его владельца.

Core `profiles.resolve_profile` получает только разрешённые, свежие источники. Поля наблюдения старше90 дней не используются. Приоритет: актуальное явно заполненное поле Food, затем согласованное Supply, затем недостающее измерение веса Gym. Пустое/невалидное поле не стирает fallback. Для расчёта прошлой тренировки профиль должен уже существовать к её времени. На каждом поле источник, event_id, observed_at и basis.

Недавние массы с разницей>10% или рост с разницей>5см, несовместимый пол/возраст отмечаются как конфликт. Пороги — правила запроса уточнения, не медицинские нормы. Конфликт приостанавливает автоматический ориентир/энергию, но не удаляет данные и не меняет сохранённую цель Food. Год рождения задаёт интервал возраста; точный день рождения не придумывается. Действующие source/receiving подписки, Supply consent и отсутствие delegation остаются обязательны.

## Детерминированный ориентир питания

Канонический `shared/nutrition_plan.py` зеркалируется дословно **только** в Food `progressor_nutrition_plan.py`; это небольшой общий алгоритм, не копия приложения Core. update-all проверяет совпадение. Изменять обе копии вместе. Обычный Food goal survey и WebApp calculation не обращаются к ИИ.

Округлённый Mifflin-St Jeor: `10×kg + 6.25×cm − 5×age + 5` для male либо `−161` для female. Это оценка энергии покоя, не всей суточной потребности. [Исходное исследование Mifflin](https://pubmed.ncbi.nlm.nih.gov/2305711/).

Продуктовые стартовые коэффициенты активности1.2/1.375/1.55/1.725; цель похудеть0.85, поддерживать1, набрать1.10. Ориентир не опускается ниже расчётной энергии покоя и округляется до25 ккал. Эти коэффициенты и шаги не являются точно измеренными или валидированными индивидуальными рекомендациями. Обычная активность **уже включена**. После тренировки цель не увеличивается автоматически.

Стартовый белок1.6 г/кг при тренировках/средней-высокой активности (в диапазоне1.4–2.0 для большинства здоровых тренирующихся по [ISSN](https://link.springer.com/article/10.1186/s12970-017-0177-8)); иначе1.0 г/кг как редактируемый продуктовый ориентир. Жиры30% энергии, углеводы остаток; эти доли — настраиваемое распределение, не назначение. Простая модель ограничена взрослыми19–78, BMI18.5–40, полными полями; при особых ограничениях/беременности/специальной диете требуется согласованная ручная цель. Не использовать ИИ для выдумывания недостающих входов.

WebApp сначала показывает ориентир и происхождение, затем отдельной кнопкой сохраняет как цель. Просмотр, изменение профиля и подключение данных не стирают ручную цель. Survey сохранение соответствует явному действию пользователя «подобрать цель». Core preview не записывает ничего в Food.

## Уведомления

Отправитель — **существующий** Food bot consumer, не новый процесс. `progressor_notifications` выполняет не более4 private batch запросов по50 пользователей за проход, продолжая со следующего пользователя через минуту. AI/provider calls отсутствуют.

Пользователь отдельно включает напоминания после тренировок и/или недельный обзор. По умолчанию оба выключены. Food хранит preferences/timezone/enabled_at и собственный delivery ledger. Core лишь возвращает подписанному локальному Food control каналу кандидатов; публичный URL этой операции закрыт.

После тренировки: задержка30 минут, возраст записи не более2 часов, запись после включения функции, свежие оплаченные Gym+Food, без backfill. Если человек увидел карточку в Food или Gym либо скрыл Food hints, сообщение подавляется. Тихие часы22–08 по выбранному IANA timezone. Недельный обзор: только при достаточном покрытии нутриента и отдельном opt-in, дневные часы12–20, после24 часов включения; не чаще1 раза в7 дней. Общий предел —1 сообщение в местные сутки.

Текст показывает остаток **до существующей личной цели по записанным блюдам**, Б/Ж/У и напоминание проверить полноту. Нет сегодняшних блюд — нет утверждения о нулевом рационе; нет цели — нет придуманного числа. MET оценка при подходящих входах остаётся отдельным диапазоном, не назначением дополнительных калорий.

Food резервирует unique(user,day) **до** Telegram send. Sent/reserved/uncertain не повторяются после рестарта. Timeout может означать уже доставленное сообщение; такие результаты не повторяются. Явный RetryAfter, означающий отказ доставки, позволяет отложенную повторную попытку того же ключа. Forbidden выключает reminders. Отключение preference между расчётом и отправкой перепроверяется. Такой режим предпочитает пропуск сомнительного сообщения дубликату.

Обзоры железа/B12 относятся к пищевым источникам из покрытых записей, а не к клиническому дефициту. Отсутствие насыщенных жиров **не означает** недостаток омега3/6: [NIH Omega3](https://ods.od.nih.gov/factsheets/Omega3FattyAcids-HealthProfessional/). Одного дня и отсутствующих блюд недостаточно для диагноза; [NIH B12](https://ods.od.nih.gov/factsheets/VitaminB12-HealthProfessional/). Дозы и начало лечения не назначаются.

## Проверки и восстановление

Core: offers8 combinations/trial/gift/signatures, both Gym surfaces/dedup/backfill, profiles/conflicts/formula/seen/private candidates. Food: owned API preview/apply, survey без AI, opt-in/account isolation, daily/weekly ledger, unknown timeout/RetryAfter/Forbidden/outage/purge. Gym: owner duration, done timestamp and прежние права. Linux tests используют временные базы и dummy providers; браузер — реальные локальные API/HTML и synthetic Telegram launches. Не утверждать физический Telegram/iPhone или реальный платёж.

Релиз публикуется обычным fast-forward в main4. Перед рабочим переключением — проверка места, свежая согласованная application backup с off-server restore. Обновление: `update-all`; проверка без переключения: `update-all --check`. Общий engine откатывает code/runtime при ошибке; **не восстанавливает старые БД поверх новых действий пользователя или платежей**. Операционный журнал фиксирует реальные SHA, проверки и архивы. Держать ограниченную политику backups, не удалять чужие архивы.
