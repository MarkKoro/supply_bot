# Проверка качества Supply

Общая [система технических и интерфейсных правил](https://github.com/MarkKoro/progressor_core/blob/main/docs/QUALITY_PROGRAM.md) находится в Core.
Добавки, профиль, анализы, расписания и отметки принадлежат Supply. Core читает
только опубликованный владельцем снимок и не пишет в эту базу.

- Для административных операций проверяйте текущую роль владельца на момент
  действия. Catalog editor не является администратором подписок. Старый callback
  и уже открытая форма не сохраняют отозванное разрешение.
- Starter trial потребляется один раз, независимо от повторов activation callback.
  Нативный тариф Stars и экспортируемый тариф берутся из одной функции. Сохранённые
  старые покупки не переписываются под новый каталог.
- Check-in сохраняет первые ответы, источник и processing/done/failed до обращения
  к модели. Конкурентный запрос не создаёт второй расчёт. Refresh — только GET;
  retry использует исходные ответы в исходном канале с общим guard.
- Успешный пустой результат допустим; Apply отключён при отсутствии изменений.
  Модель не заполняет дозы и не добавляет произвольную позицию вместо пустого результата.
- Старый AI dose не становится введённой дозировкой при показе или применении.
  Доза берётся из собственного user_supplement_settings. Повтор taken сохраняет
  первый снимок надписи; явный unmark → taken может зафиксировать новую надпись.
- Перед применением перечитывайте собственный stack/complex/taken: уже принятая
  позиция или член комплекса не удаляется/не дублируется устаревшим ответом ИИ.
- UTC/GMT является допустимым подтверждённым выбором; его наличие не означает
  незавершённую onboarding. Обновление не заставляет старого пользователя проходить её снова.
- Статистика загружает ограниченное окно пакетно. Долгое чтение не держит writer lock,
  неизменный каталог достижений не переписывается на каждую отметку.
- Загрузка опроса сама обновляет активный экран. При ошибке остаются исходные ответы
  и кнопка безопасного чтения; устаревший retry/apply не предлагается. Версия запроса
  защищает переход Сегодня → Завтра → Сегодня. Исторический результат не закрывается guide.

Проверяйте `test_checkin_atomic`, `test_checkin_policy`, `test_quality_access`,
`test_quality_statistics`, нативный reminder и обе роли. Runtime устанавливается
из `requirements.txt` с полным `constraints.txt` в отдельный venv. Не запускайте
дополнительного consumer и не делайте платных запросов для регрессий.


## Независимый запуск общего интерфейса

Локальный `webapp/assets/progressor-bootstrap.v1.js` — точная distribution copy канонического `Core/shared/bootstrap.v1.js`. Он захватывает исходный Telegram launch и не заставляет собственные запросы бота ждать Core. Общий UI по-прежнему загружается из единственного Core асинхронно; backend Core в бот не копируется. При правке bridge обновляйте canonical и все три копии вместе: update-all сверяет байты. При cross-navigation SDK может возвращать обновлённый proof исходного бота; не переименовывайте его источник в текущий продукт. Если sessionStorage недоступен, собственный бот работает, а неподтверждённый переход не выполняется.


Payment menu consistency: three primary periods (1/6/12 months), equal RUB/Stars buttons per row, retained extra periods with a return action. Existing quotes, SKUs, receipts, native expiry and provider confirmation are unchanged. Canonical progressor_bot.py must match Core shared/progressor_bot.py. Food menus read current billing settings. Legacy callback names remain compatible.
