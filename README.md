# ГУДы БАДы / GoodyBady

Telegram-бот, WebApp на FastAPI и отдельный обработчик очереди помощника.
Общая SQLite-база хранит каталог, пользовательский план, отметки, напоминания,
подписки и задания. Точка продолжения технического аудита — [AUDIT.md](AUDIT.md).

## Анализы в профиле

В боте: кнопка «🧪 Анализы» или `/labs` (`/analyses`). Документы и фотографии
сохраняются через общий с WebApp обработчик; отправка одного файла через оба
входа не создаёт дубль. После загрузки доступны проверка страниц результатов,
ручной ввод любых показателей, изменение даты/лаборатории и переход прямо к
этому анализу в приложении. Пример ручного ввода, одна строка на показатель:
`Магний;0,8;ммоль/л;0,7;1,0` или `ПЦР;не обнаружено`.
ИИ-распознавание в боте запускается только после отдельного согласия.

В WebApp загрузка/фото и ручной ввод доступны вверху раздела; обзор, документы
и динамика разделены. Обучение включает анализы; повтор доступен из настроек
и кнопки «?» в анализах. Сохраняются открытый модуль, подраздел и позиция;
возврат из бота/фона обновляет видимые данные. Черновик во время ввода сохраняет
свои поля; конфликт с правкой из другого окна отклоняется. Можно показать
свежую версию, а затем вернуть свой черновик для сверки перед подтверждением.

Референсы для пола/возраста подставляются по явному нажатию из самого бланка:
поддерживаются однозначные подписи «Мужчины/Женщины» и интервалы возраста
вида «18–65 лет». При отсутствии профиля/даты, сложных условиях или возрастной
границе ничего не угадывается. Подтверждённые диапазоны не пересчитываются
после изменения профиля. Подсказки названий — справочник для ввода; можно
сохранить любой показатель, единицу и качественный результат из лаборатории.

Связанные позиции показывают последний отмеченный приём и записанные на
эту дату дозы. При новом добавлении можно явно повторить свою прежнюю дозу.
Для приостановленной личной записи доступно отдельное возобновление,
с сохранением текущей дозы и настроек; оно не запускает весь комплекс.

Раздел «Анализы» хранит документы, проверенные результаты и динамику вместе
с отметками приёма. Поддерживаются PDF (до 20 страниц), JPG/PNG/WEBP,
DOCX/XLSX, CSV/TXT/JSON; один файл до 12 МБ, всего до 200 документов/200 МБ.
Таблицы с колонками «Показатель», «Результат», «Единицы», «Референс» либо
ref_low/ref_high читаются локально. Фото и сложные бланки можно распознать
через OpenAI только после разрешения пользователя. Проверка результатов
обязательна перед включением в динамику. Неизвестные названия/единицы и
текстовые результаты, текст референса и отдельные даты строк сохраняются;
общие нормы из старого помощника не подставляются. Изображения внутри DOCX/XLSX
нужно загрузить отдельным фото/PDF. Несохранённые черновики удерживаются в
текущей сессии, а подтверждённые результаты и документы хранятся постоянно
до удаления пользователем.

Для OCR и необязательного пояснения истории используется отдельная
OPENAI_LAB_PARSE_MODEL (по умолчанию gpt-4.1-mini). До 20 обращений к ИИ за
календарный месяц на аккаунт, включая неуспешные/прерванные вызовы; чтение
таблиц, просмотр истории и сравнения не расходуют этот лимит. Сохраняются
фактические usage-токены. Повторный файл и повторное открытие актуального
пояснения не вызывают ИИ снова. Пояснение описывает наблюдения и вопросы,
не назначает дозы/курсы и не утверждает причинную связь между БАДом и анализом.
Связанные карточки добавляются только по выбору пользователя, с его дозой;
существующие дозы и настройки не переписываются, пауза снимается только отдельным явным действием.

API и assistant_worker должны работать с одним DB_PATH. Worker обрабатывает
распознавание/пояснения и удаление исходных файлов после очистки данных.
Файлы лежат рядом с БД в uploads/labs, вне публичных ресурсов; скачать их
может только владелец с подписанной Telegram-сессией. Новые отметки приёма
сохраняют дозы плана на эту дату; для старых записей неизвестная доза
не заменяется сегодняшней. Без отметки приём остаётся неизвестным.

## Установка

Проверенная среда аудита: Python 3.12.14. `requirements.txt` фиксирует прямые
зависимости этой среды, а не обещает совместимость с будущими версиями.
Транзитивные зависимости и целевую серверную ОС проверять при развёртывании.

Из корня проекта:

```sh
python -m venv .venv
```

Активировать окружение: PowerShell — `.venv\Scripts\Activate.ps1`,
Linux/macOS — `source .venv/bin/activate`. Далее:

```sh
python -m pip install -r requirements.txt
python -m pip check
python init_db.py --self-test
```

Скопировать `.env.example` в `.env`, заполнить TG_TOKEN, OWNER_TG_ID и параметры
публикации. Не заменять существующий `.env` целиком при обновлении.
У бота, API и worker должны совпадать рабочая директория и **абсолютный DB_PATH**.
Процессы должны иметь доступ на запись к базе, её каталогу и `data/uploads/labs`.

OpenAI SDK должен поддерживать используемый `client.responses.create`;
[официальная инструкция](https://developers.openai.com/api/docs/libraries).
Фиксированный SDK проверен локально без обращения к API. Модели, prompts и
стоимость запросов этим изменением не меняются. Доступность моделей для рабочего
аккаунта и сроки миграции см. в AUDIT.md.

## База и библиотека

Новая установка:

```sh
python init_db.py
python seed_import.py --rich-supplements data/seed_rich/supplements_rich.jsonl --curated-stacks data/seed_rich/curated_stacks.jsonl --curated-items data/seed_rich/curated_stack_items.jsonl
python init_db.py --check
```

Пути `data/seed/*` из старой инструкции больше не используются. Отдельного
`interactions_rich.jsonl` в репозитории нет: связи находятся внутри rich-карточек.
Часть связей относится к группам/условиям или ещё не сопоставлена с карточкой;
их исходный текст сохраняется. Статус разбора — GB-29 в журнале.

Полный ручной импорт обновляет существующие карточки из файла. Перед ним нужна
резервная копия, особенно если каталог редактировался в админке. Auto-seed бота
при `AUTO_SEED_ON_START=1` только добавляет отсутствующие карточки, сохраняя
существующие правки и скрытые позиции. Ошибка импорта откатывает весь пакет;
исправить исходные данные и повторить импорт, не удалять базу.

## Запуск

После миграции запустить три отдельных процесса из одного корня проекта:

```sh
python bot.py
python -m uvicorn webapp_backend:app --host 127.0.0.1 --port 8000
python assistant_worker.py
```

Это три команды для трёх процессов, а не последовательность в занятом терминале.
На сервере нужен менеджер процессов с перезапуском. Для одного Telegram-токена
запускается один polling-процесс `bot.py`. Напоминания и сверка ожидающих оплат
выполняются в процессе бота; API сам по себе их не заменяет. Worker нужен для
заданий помощника; его UI пока скрыт существующим флагом.

FastAPI обслуживает HTML по `/`, API по `/api/*`, ресурсы по `/assets/*`,
возврат после оплаты по `/payment-return.html`. Внешний HTTPS reverse proxy
должен направлять **все** эти пути на один процесс API. При публикации под
`/supply/` proxy снимает этот префикс. В `.env`: WEBAPP_URL — полный URL
с завершающим `/`, PUBLIC_BASE_URL — origin, WEBAPP_PUBLIC_PATH — `/supply`.
YOOKASSA_RETURN_URL можно задать явно; иначе он собирается из двух последних.
Не публиковать корень репозитория или `data/` как статическую директорию.

`GET /health` проверяет ответ процесса, но не Telegram, оплату или целостность
базы. WebApp авторизует запросы подписанным Telegram initData; открытие в
обычном браузере без Telegram не является рабочим входом.

## Обновление, копия и восстановление

Перед обновлением остановить бот, API и worker; сохранить текущую версию кода,
конфигурацию и снимок базы. Копия создаётся без миграции исходника:

```sh
python init_db.py --backup backups/before-update.sqlite3
python init_db.py --db backups/before-update.sqlite3 --check
```

Имя копии каждый раз должно быть новым: существующий файл не перезаписывается.
Используется SQLite backup API, включающий зафиксированные записи WAL.
Копирование только `.sqlite3` работающего процесса может их пропустить.
Также сохранять `data/uploads/` и конфигурацию отдельно от Git с ограничением доступа.

После обновления кода: установить зависимости, выполнить `--self-test`, затем
`python init_db.py` и `python init_db.py --check`, после успеха запустить процессы.
При ошибке миграции не запускать остальные процессы поверх непроверенного состояния.

Для проверки восстановления использовать **новый путь**, например
`backups/restore-check.sqlite3`: создать туда копию снимка через `--db`/`--backup`,
проверить `--check` и выполнить миграции с `--db` на этой копии. Не подменять файл
базы под работающими процессами. Для отката остановить все три процесса, выбрать
проверенную копию новым абсолютным DB_PATH и согласованную версию кода; старый
файл и его WAL оставить для разбора. Возврат старой копии теряет более поздние
записи: платежи после снимка сверить с провайдером до возобновления выдачи доступа.

## Автономная проверка

`python init_db.py --self-test` не читает рабочий DB_PATH, не требует токенов и
не обращается к Telegram/ЮKassa/OpenAI. Во временной базе проверяет:

- повтор миграций и сохранение полей при частичном изменении профиля;
- отклонение NaN, откат составной операции и повтор события оплаты;
- единственность активного задания, окончательность отмены и квоту;
- резервную копию WAL, запрет перезаписи, миграцию восстановленной копии и integrity.

`--check` открывает существующую базу только для чтения; отсутствующий путь не
создаётся. Это проверки SQLite, не полноты всех продуктовых сценариев.
Подробные API/браузерные регрессии и ограничения перечислены в AUDIT.md.
Новый workflow CI не добавлен: пользователь просил не создавать файлы приложения.
Команда `--self-test` готова для запуска в существующей системе CI.
